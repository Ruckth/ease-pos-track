Prove direct Convex RPC cannot bypass the gateway, and block redirects to a different origin.

The runner operator uses an enrolled macOS execution identity and restricted Keychain access. On each installed combination, at least 95% of 40 nonempty representative runs must finish committing within the cap, including slow model responses and a locked-host case counted in availability diagnostics. If timing fails, narrow the batch or remain manual. Hard model cancellation is a separate host capability.

Send a deduplicated in-app Operations alert to active Owners when no expected heartbeat arrives for two scheduled intervals, when a runner key has 14 days or 3 days left or expires, and when an external delivery remains unknown for 24 hours. A separate server job evaluates even when the runner is asleep. Record first seen, last observation, acknowledgement and resolution. An opted-in backup operator can receive a minimal external nudge once verified email exists. Simulate each threshold, repeated checks and recovery with a controlled clock. When an external send or AI disclosure begins

The last database mutation is the ordering point for revocation. Work may be queued or buffered privately beforehand. Immediately before crossing the trust boundary, the designated dispatcher runs a serializable begin-attempt mutation. It rechecks current authority, eligibility, mode, generations, lease and budget, freezes the exact bytes and destination by digest, and consumes a one-use nonce bound to this executor, attempt, expiry and purpose. Its commit starts exactly one authorized attempt for policy purposes. No provider call or model-visible tool output may occur before that commit. External I/O runs outside the database transaction.

If withdrawal, pause, restriction or a conflicting rule change commits first, begin-attempt must fail with zero provider bytes, calls and budget charges. If begin-attempt commits first, the original executor may start exactly one bounded send or handoff of those exact bytes to that exact destination even if the change commits before the network call. Give it at most five seconds from authorization to initiate; discard an unused permit after that deadline or if the clock bound cannot be established. A request already initiated may finish afterward. Subsequent attempts, batches, repairs and assignment writes need fresh authorization under current policy. Describe this small in-flight window in settings. A change never promises recall. For AI, only one schema-validated provider reply is needed. The broker commits the result and finish receipt; the driver terminates locally without sending a subsequent tool result upstream. Terminal turn and host acceptance tests.

An attempt is not a reusable bearer. Record its committed start before I/O, disallow reading a spent permit into another process, turn off automatic client/SDK retries, and reject stale or overlapping workers. Only the original successful mutation response can authorize the live executor once. Loss of that response or a crash after commit is an unknown or unused attempt. Do not replay the same permission. For Ticket alerts, any permitted retry gets a new checked attempt for the original logical intent, exact payload and provider idempotency key, within its validity window. For AI, do not replay an uncertain tool response; treat it as possibly disclosed and re-evaluate the next eligible batch. Record only non-secret references, digests, timestamps and safe outcomes.

For alerts, bind authorization to event, stable intent, recipient, category, channel, consent vector, destination and binding generation, visibility generations, payload digest and provider identity. AI uses separate one-use authorizations for the model-visible T3 handoff and the subsequent provider socket handoff, each bound to the actual approved provider/endpoint and host occurrence, policyGeneration and ruleRevision, sponsor, fence, cutoff, candidate aliases and Ticket versions, data-policy state and exact sanitized batch digest. Each boundary has its own five-second start deadline. Delayed, replayed or buffered T3 output cannot authorize a provider call. If transport replay cannot be prevented, the broker stays off. The first fetch may stage the projection inside the isolated broker only. Its IPC result, tool stdout, T3 transcript and provider input remain empty until disclosure authorization commits. If the installed host cannot enforce that separation, leave the broker disabled.

Use deterministic barriers immediately before the authorization commit and after commit but before transport starts. For email and LINE, run both orderings for withdrawal and immediate re-opt-in under the channel default and Project override. For AI, run both orderings for pause, a newly confident rule and reclassification as restricted. When the change wins, the recording transport must receive nothing. When the commit wins, at most the one exact authorized request can start within five seconds; block later retries, extra batches, changed payloads, late writes and new charges. Also exercise expired permits, duplicate workers and both crash windows. Convex orders database mutations; it cannot make external transport part of their transaction.

Customer visibility and password rules

A customer can use a Ticket surface only with a live, active customer, current membership of an active Project, and that customer's own Ticket. An archived Project disappears from lists, counts, search, activity, attachments, deep links and notification projections. All new customer writes stop. An archived Ticket is also unavailable to the customer. A removed member and a same-Project peer get the same unavailable response as a missing Ticket. Apply this check inside read, projection, write and retry operations. Staff restoration retains original ownership. Restored records reappear only when all current access checks pass.

All password writes use one server policy on signup, change and saved-code recovery. Accept 15–100 Unicode code points, reject surrounding Unicode whitespace and common passwords, allow spaces inside the phrase, and use the pinned component's NFC hashing and verification rules. Pass the same minimum to the component setter on all three paths. Normalize input consistently to NFC before applying code-point limits and writing or verifying. Run paired decomposed/composed boundary examples against the pinned component before release. Preserve the normalized password on all three paths. Show bilingual rules and allow paste/password managers. Test 14/15/100/101 code points, Thai, astral emoji, canonical equivalence, whitespace and a common password through browser and raw RPC. A normal change verifies the old password and revokes other sessions. Recovery revokes all.

Inject a failure after the password write and before transaction completion. The old password, recovery code, sessions and ownership must all still work. After success the old credentials fail. A lost success response reconciles with the new password. Include disabling the account during recovery and verifying old subscriptions and media reads are denied.

The pilot is text-only. Turn off customer and staff upload initiation and new media access on every pilot UI and API route. Data restore and access re-enrollment

Before any data restore the deployment operator closes application traffic and independent external egress, stops workers, and records the previous deployment epoch and policy-generation high-water marks in the external recovery manifest. A restore is a planned maintenance operation. For the manual pilot an offline, operator-controlled maintenance switch and external release manifest suffice. The data store being restored cannot open its own traffic or mint its own valid epoch. If the platform cannot prove the switch covers direct Convex calls, put the deployment in maintenance or restore into an isolated deployment with no public sessions, keys, workers or live provider credentials. Never restore in place with active clients.

Advance the independent recovery epoch before replacement. Configure it outside the restored database for every auth wrapper, direct RPC, HTTP gateway, broker, provider transport and optional sender. Require an exact match with the installed database epoch. Quarantine is the default on missing evidence or mismatch. Invalidate all browser admissions, component sessions and refresh credentials, pending sign-in flows, action proofs, invitations, outstanding reset/recovery grants and all personal, operator and runner keys. Invalidate every pre-restore saved-code digest and advance its generation unconditionally before re-enrollment. Pause all routing policies, invalidate fences, proposals, pending provider grants and candidate caches. Set restored policyGeneration above the maximum recorded in the external manifest and bind future grants to the new recovery epoch. If the maxima cannot be proven, hold the old deployment closed and rebootstrap under a disjoint epoch/namespace.

Reconcile staff disable, role and subject bindings, customer state/membership, archive/privacy flags, password or account changes, restricted classifications and revocations from trusted post-snapshot evidence. An uncertain principal or Project remains quarantined. A successful Google sign-in or an old password alone cannot reactivate a restored identity. Reopen only reconciled browser identity first. Restore never transfers Ticket ownership. The Owner must explicitly reapprove each AI policy with fresh proof and re-enroll newly issued host credentials; old keys can never regain authority. Recovery of the doctor, broker and channel worker is optional and independent of serving the reconciled manual pilot.
