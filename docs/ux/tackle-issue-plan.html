Explain what search and counts include

  • Source reviewed
  • Data honesty

Evidence

Lane totals, loaded rows and capped indexed search describe different populations. The sample High threshold of 80 disagrees with the app’s urgency bands.

  • Inspect the reference implementation

Implementation

  1. Staff text search runs against the authorized Project and selected lifecycle. Honor the exact Ticket-number path, the 200-character/16-token bounds and the limit of 50 returned matches. Keep the selected view when text changes. In Board, group returned matches by status, show bounded counts, and clear search to return to the prior lane. Mark a capped set with Refine search. In browse mode offer Load older when more pages exist.
  2. Apply tag, urgency and other local filters to the returned or loaded summaries. Preserve tag OR within a rule, AND across rules, date ranges and deterministic sorting with unset urgency last. Sort before paginating Table and reset its page when criteria change. Preserve Board workflow order and independent lane pages. Merge duplicate IDs by latest version.
  3. Use canonical bands Unscored, Low 1–25, Medium 26–50, High 51–75 and Critical 76–100. Label the one-tap shortcut “High or critical” and include scores 51–100. Active staff scope includes Waiting and excludes Resolved. Resolved is a workflow status. Archive is a separate lifecycle. On the compared branch customer Active also includes Waiting, and its counts/search are scoped to loaded, owned rows.
  4. In a partially loaded browse lane keep the filtered count, loaded count and server total distinct. For example, show “2 matching among 20 loaded · 80 total” and Load older. If totals are unavailable, show the first two numbers. Customers see “You have no Tickets in this Project” only after exhausting their owned, unfiltered list. For an empty filtered list offer Clear filters or Load older as applicable.

Implementation

  1. On opening detail capture Project, view, lane, search, filters, sort, page, visible row ID, scroll and focus. Restore them on Back or Close.   2. Disable only the pending Ticket action. On a version conflict show the authoritative status.   3. Show the owning Project on Resume draft. Closing returns to the list and retains in-session text, files and annotations. A Project switch keeps the captured draft owner. Explain when a draft is session-only. Use its existing request identity for retry after an uncertain submit. Keep a confirmed Ticket reference even if its detail read fails. Archive and restore use their existing access and version checks.
